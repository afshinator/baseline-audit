baseline-audit

How it decides

Each package falls through these rungs in order. First match wins, so a package never gets further than the first thing that blocks it.

1

mapped to a native replacement?

No entry in data/mappings.json. The tool has no opinion.

nokeep
2

every target ≥ feature support?

Any browser in your target set is older than the platform feature.

noblocked
3

library gzip − polyfill gzip > 0?

The polyfill is not cheaper than the library. Skipped when sizes are unmeasured.

noblocked-cost
4

any comparable engine in targets?

Every gate came back unknown. Establish real targets first.

nounverified
5

usage analysed for this package?

Mapped from the e18e manifest, but no keep-signal list exists for it.

nocheck
6

partial, or keep-signal found?

Native covers only part of it, or a keep_if hit in an importer, including one hop through a re-export.

yescheck
7

otherwise

Baseline-safe against your targets, and nothing in your code uses the gap.

swap
gates read web-features support floors  ·  bundlephobia gzip − overrides polyfill  ·  keep_if regex over importers (+1 hop)
